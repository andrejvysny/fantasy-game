## 6. Notes, differences, NOT RUN

Prop patch: the addon README says a patch of a textured material embeds the textures. Observed: wrapper has `ext_resource` Texture2D paths to the delivery's `model_0.png`/`model_1.png` and one `StandardMaterial3D` sub-resource (~1.3 KB). No embedded image data, so the patch approach is kept (no upstream issue). Patched material has default metallic 0; matches `make_dielectric`.

Legacy spruce: the GLB ships a `TrunkCollision` StaticBody3D (convex hull, 15 pts, AABB x -0.44..0.48, z -0.47..0.43, y 0..9.22). `variants.json` has no trunk radius, so the policy cylinder is an estimate from that hull: r = 0.46 (half of mean x/z extent), h = 9.22. The game's own convex shape is dropped by `integration_asset` (the policy is the single source).

Legacy spruce slot `default` is not mapped by `fantasy_spruce` (`set-policy` reported 1 unmapped slot); the mesh has one surface, which is `spruce_vertexcolor`, and it is overridden. Nothing visibly missing.

Visual parity (honest differences): nature trees/boulder (row A vs B) render with the same shared game materials, no visible difference. Legacy spruce row B uses the valley `_tree_material()` params including fade/dither; row A uses `spruce_legacy.tres` without them; no visible difference at a single instance. Props/grass preserve or dielectric-patch the same GLB material; same look. Differences not covered: valley MultiMesh/instance fade, tree occluder, wind per instance, LOD/visibility ranges, per-tree jitter overrides. Row B pine/spruce/boulder use `NatureAssets` meshes (game path), row A the delivered GLB geometry; vertex/UV2 data identical by construction, not hash-compared.

Pre-existing before this work (not mine, left as-is): `project.godot` rendering block reorder (removed default `screen_space_aa=0`, `use_taa=false`, moved `msaa_3d`) and re-import diffs in `tree_stump_*.import`, `wooden_lodge_*.import`. Verified unchanged by my runs.

NOT RUN: editor plugin dock manually (smoke only), drag/Place, `update`/`rollback`, running the test scene with the plugin explicitly disabled in the editor (verified instead by dependency closure: no `res://addons/` reference, and `--script` runs never load editor plugins), device/iPad, valley integration of wrappers, `godot_static_source_v1`.
