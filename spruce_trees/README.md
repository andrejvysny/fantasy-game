# Spruce trees for Godot 4

45 low-poly spruce trees (38 live, 7 dead) as GLB scenes, generated by `spruce_hybrid.py` + `spruce_variants.py`
(round 12: foliage darker towards the trunk). Checked in Godot 4.6.3 (see "Verified" below).

## Quick start

1. Copy this `spruce_trees` folder into the root of your Godot project, so it becomes `res://spruce_trees/`.
   (The demo scenes expect that path. Elsewhere works too: move the folder inside Godot's FileSystem dock, or
   fix the paths when Godot shows the "missing dependencies" dialog.)
2. Pick the model set that matches your renderer (Project Settings > Rendering > Renderer > Rendering Method):

   | Rendering method | Use | Why |
   | --- | --- | --- |
   | Forward+ (desktop default) or Mobile | `models/` | Standard glTF: vertex colours are linear, Godot shows them correctly |
   | Compatibility | `models_compatibility/` | This renderer ignores the vertex-colour colour space and shows the numbers as sRGB, so this set stores them sRGB-encoded |

   With the wrong set the colours are clearly off (measured: median error 72 of 255 instead of 1-2).
   You can delete the set you do not use.
3. Drag a `.glb` into your scene, or in code:

   ```gdscript
   var tree: Node3D = preload("res://spruce_trees/models/spruce_M_normal_std_s9.glb").instantiate()
   tree.position = Vector3(4, 0, -2)
   add_child(tree)
   ```

Demo scenes: `spruce_trees_lineup.tscn` (Forward+ / Mobile) and `spruce_trees_lineup_compatibility.tscn`
(Compatibility) place all 45 trees in rows with name labels, a sun, a sky and a camera.

## What is inside every GLB

```
spruce_M_normal_std_s9      Node3D (scene root, named after the tree)
├─ Tree                     MeshInstance3D: one mesh, one StandardMaterial3D
└─ TrunkCollision           StaticBody3D (Godot creates it from the "-convcolonly" name suffix)
   └─ CollisionShape3D      ConvexPolygonShape3D around the trunk (follows the root flare and taper)
```

| Property | Value |
| --- | --- |
| Units, axes | metres, Y up, origin at the centre of the trunk base (the tree stands on y = 0) |
| Size | S about 4 m, M about 6 m, L about 8 m tall; long / tall trunks up to 11.5 m. Exact height, crown radius and triangle count of every tree are in `variants.json` |
| Triangles | 1,612 to 4,856 per live tree, 357 to 1,392 per dead tree |
| Material | Vertex colours used as albedo, double sided (cull disabled), roughness 1, metallic 0. No textures |
| Shading | Flat (faceted): the normals are split per face on purpose |
| Colours | Foliage dark blue-green at the trunk, lighter yellow-green at the tips of every skirt and branch |
| Collision | Trunk only. Branches and foliage have none. Delete the `TrunkCollision` node if you do not want it |
| LOD | Godot generates mesh LODs on import (default import setting); nothing to do |

## Names

`spruce_<size>_<shape>_<trunk>[_<spacing>]_s<seed>.glb` for live trees, `dead_<size>_<trunk>[_<spacing>]_s<seed>.glb`
for dead ones.

- size: `S`, `M`, `L`
- shape: `slim`, `normal`, `wide`
- trunk: `std`, `long` (2 x bare trunk), `tall` (3 x)
- spacing: vertical spacing of the branch tiers: `dense`, `open`, `layered`, `bottom_dense`, `top_dense`, `irregular`, `gapped`. No spacing in the name means even
- seed: a different random tree of the same recipe

## Tips

- **One shared material:** every GLB brings its own copy of the same material. To use one for all trees (and to tweak it in one place), open a GLB's Advanced Import Settings, extract the material to a `.tres`, and set it as external material for the others. It must keep `vertex_color_use_as_albedo = true`.
- **Forests:** for hundreds of trees use `MultiMeshInstance3D` with the `Tree` mesh. Collision then has to be added separately, for example one `StaticBody3D` per tree near the player.
- **Wind or colour tweaks:** the vertex colours arrive as `COLOR` in a custom shader, so a ShaderMaterial can reuse them.

## Regenerating

From the project folder with the scripts, in Blender 5.x:

```
blender -b -P spruce_variants.py -- --godot <path>/spruce_trees/models --godot-compat <path>/spruce_trees/models_compatibility
```

Or from Blender's Python console: `sv.build_scene(godot_dir=..., godot_compat_dir=...)` after `import spruce_variants as sv`.

## Verified (Godot 4.6.3, Linux, software rendering)

- Import of all 90 GLBs: no errors or warnings. Every scene loads and has exactly the structure above.
- Height of every tree within 0.05 mm of `variants.json`. Base at y = 0. Collider radius within 0.1 mm of the trunk mesh.
- Colours, unlit render of the M tree against the generator's colours: median error 1/255 (Forward+ with `models/`), 2/255 (Compatibility with `models_compatibility/`).
- Rendered with Forward+ (Vulkan, lavapipe) and Compatibility (OpenGL, llvmpipe). Not rendered on real GPU hardware or with the Mobile renderer. Mobile follows the same colour rule as Forward+ according to the Godot documentation. Other Godot 4 versions: the GLBs are standard glTF 2.0; the demo scenes use the Godot 4 scene format.
